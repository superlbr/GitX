# GitX 界面设计规范

> 本文是 UI 的唯一事实来源。实现（`src/ui/theme.rs` 常量、`app.rs` 布局、`geometry.rs` 判据锚点）
> 以这里的数字为准；视觉改动先看这张图，再动代码。
>
> 定位：**现代化清爽的 Git 客户端**（向 GitHub Desktop / Fork 靠），不再是任何既有产品的复刻。
> 大留白、柔和灰阶、清晰信息层级；颜色只给状态和层级，不装饰。
>
> 可视化预览：[design-preview.html](design-preview.html)（浏览器直接打开，右上角可切亮/暗）。

## 1. 设计原则

1. **灰阶打底，主色点睛**：界面 95% 是白与灰的层级；主色 `#0969DA` 只出现在选中、链接、主按钮、当前分支。
2. **信息靠层级，不靠颜色**：列表正文一律 `TEXT_PRIMARY`；主次用字号字重和灰度拉开，SourceTree 式「深色正文 + 浅灰次要」作废。
3. **1px 分隔线分区**，不再用底色带硬切（侧栏、表头、状态栏除外，它们是 chrome）。
4. **4/8 网格**：一切间距、尺寸落在 4 的倍数上。
5. **弹窗即闸**：所有不可逆操作先过确认卡；反馈走 toast，不用弹窗报成功。

## 2. 首页（主窗口）布局

```
┌──────────────────────────────────────────────────────────┐
│ HEADER 46pt  🚦 仓库tab(胶囊)  分支·↑↓      动作按钮组 »  │  ← 白底 + 下 1px 分隔线
├────────┬─────────────────────────────────────────────────┤
│ SIDEBAR│  LOG 区（表头 28 + 行 28 × N，可滚）              │  ← 侧栏 188pt 灰底
│ 188pt  ├─────────────────────────────────────────────────┤
│ 分组   │  STAGING 带 240pt：文件表 330pt │ 差异区           │  ← 可拖高，1px 分隔
│ +筛选  ├─────────────────────────────────────────────────┤
│        │  STATUS 24pt                                   │  ← 白底 + 上 1px 分隔线
└────────┴─────────────────────────────────────────────────┘
```

| 区域 | 尺寸 | 要点 |
|---|---|---|
| HEADER | 46pt，横贯整窗 | 红绿灯 inset 92pt 不变（`TITLE_INSET`）；**最左一格固定是「首页」tab**（§2.1），其后才是仓库 tab；tab 均为胶囊开关（高 26、圆角 999，选中 = 主色浅底深字）；选中分支名 12px + `↑↓` 计数；右侧动作按钮 28px 命中、圆角 6、hover 浅灰；窗口收窄时溢出收进 `»` 菜单——**只有仓库 tab 那一串会被收**（它是唯一无上限的一条：仓库想加多少有多少），「首页」「＋ 添加仓库」和右侧那 11 枚按钮一律平铺，因为它们在 860 地板上装得下；收的是**尾部连续一段**（前缀保序，不打乱人的视线），`»` 自己占一格宽度、点开后是溢出那几本的名单 |
| SIDEBAR | 188pt 固定，灰底 | 分组头 = 11px 灰字 + 右对齐计数，无图标；子项行高 26，选中 = 浅蓝药丸（圆角 6）；当前分支 = 蓝点 + 中黑字；底置筛选输入框 26pt |
| LOG | 表头 28pt + 行 28pt | 列：**图 48（可拖 48…320）** \| **提交号 66（可拖 48…240）** \| 提交信息（弹性）\| 作者 96 \| 日期 78；选中 = 浅蓝底 + 左缘 2px 主色条；hover 浅灰；虚拟行（未提交）浅灰底整行；ref 药丸见 §4.5。头两列的边界上各压一条 6pt 命中条（压在 1pt 竖线上），hover 换 `ResizeEast`、按住左右拖；**松手那一帧**才落库（键 `gitx_col_graph_w` / `gitx_col_sha_w`）。拖图列买的是**车道**（道距钉死 10pt，96pt 装得下 8 道），拖提交号买的是**哈希位数**（见 §7） |
| STAGING | 默认 240pt，可拖 | 文件表 330pt：行高 24，状态色块 12pt 圆角 3，圆角勾选框 13pt；底置提交框（摘要 + 三行描述 + 修正勾 + 主按钮）；右侧差异区：hunk 头灰底、增删行浅绿/浅红整行底；hunk 头右端那枚按钮跟着这一格是什么走（工作区 = 暂存/放弃区块，提交 = 回滚区块，贮藏不出按钮） |
| STATUS | 24pt，横贯整窗 | 左：分支 · ↑↓ · 进行中操作；右：仓库路径；11px 灰字 |

窗口最小尺寸 `MIN_W 860 × MIN_H 394`（= HEADER 46 + LOG 下限 84 + STAGING 240 + STATUS 24；
LOG 下限 = 表头 28 + 2 行 × 28）。**LOG 区不允许归零**：`46+240+24=310` 那种算法在最小尺寸下
给出一个看不见任何提交的窗口，那是坏掉的尺寸而不是紧凑的尺寸。STAGING 带可拖，档位
`120 … 窗口余量`。

**空态（没有打开仓库时）**：产品停在「首页」tab（§2.1）——首页里给出
`[打开仓库…]`（主色）`[克隆仓库…]`（幽灵）与一行「还没有添加仓库」的说明。
仓库视图那套 LOG 居中空态（20/600「还没有打开的仓库」+ 说明 + 两枚按钮）仍留在代码里作兜底，
但空仓库时不会走到；`home=false` 且 `repo=None` 的组合只由判据构造。

### 2.1 首页 tab：仓库列表（A）+ 代码托管（少量 B）

顶栏最左是**固定**的「首页」tab（用户 2026-10-26 拍板）：它排在所有仓库 tab 之前，不随书签
列表滚动；选中时仓库 tab 全部回未选中态。点任一仓库 tab 或打开仓库即离开首页。
首页**整页替掉侧栏 / 日志 / 暂存带**（那三块都对着「当前仓库」，而首页还没选仓库），
只保留顶栏与状态栏。

```
┌──────────────────────────── 首页 ─────────────────────────────┐
│  首页                                                    20/600 │
│  打开一个仓库继续，或添加新的仓库。                      13 次要 │
│  [打开仓库…]（主色）  [克隆仓库…]（幽灵）                        │
│                                                                │
│  仓库                                                 N 个     │
│  ┌──────────────────────────────────────────────────────────┐  │
│  │ gitx                                        main · ↑2 ↓0   │  │ 54
│  │ /Users/……/gitx                                            │  │
│  └──────────────────────────────────────────────────────────┘  │
│                                                                │
│  代码托管                                              11 次要 │
│  [GitHub] acme/app                              [在浏览器打开]  │
└────────────────────────────────────────────────────────────────┘
```

| 部件 | 规格 |
|---|---|
| 正文宽 | `HOME_MAX_W 720`，两侧留白（窗口地板 860 时仍各留 70）；顶部留 `HOME_TOP 32` |
| 标题 | 「首页」20/600 `TEXT_PRIMARY` + 13px `TEXT_SECONDARY` 说明 |
| 主按钮 | `打开仓库…` 主色实底白字、圆角 6；`克隆仓库…` 幽灵（`.small()`） |
| 仓库卡 | 高 `HOME_CARD_H 54`、圆角 `8`、白底、1px `BORDER_SUBTLE`；名字 14/600 `TEXT_PRIMARY`、路径 11 `TEXT_MUTED`；右端备注 11 `TEXT_MUTED`（当前仓库 = 分支 · `↑↓`）；当前仓库铺 `ACCENT_SOFT` + `ACCENT_LINE` 边；**整卡可点** = 打开那个仓库 |
| 卡片间距 | `HOME_CARD_GAP 8`；列表在垂直滚动区里，窗口矮时可滚 |
| 代码托管（少量 B） | 只在当前仓库快照的远端能认出 GitHub / Gitee / Codeup 时画：平台药丸 11/600 `ACCENT_INK` on `ACCENT_SOFT` + `ACCENT_LINE`、`owner/repo` 12 `TEXT_PRIMARY`、右端「在浏览器打开」小按钮；认不出整块不画 |
| 空列表 | 12px `TEXT_MUTED`「还没有添加仓库：用上面的……开始。」，不画假卡片 |

**「详细 B」分两半**：PR 列表那一半已经落地，但落在 §2.2 的**看板**（侧栏整栏替换），
不在首页这一页——首页仍然只给「这个仓库属于谁 + 打开主页」那一小块。CI 状态与合并动作
还没接：`check-runs` 是第二个端点，合并/重跑是写操作，各自要先想清楚确认档位。

> 早先设想过的「侧栏 `最近 / 分组`」没有落地：当前首页是整页仓库列表。等仓库多到需要分组时
> 再回来做那一档；数据库那列 `repos.group_name` 已经在了，不用重建库。

### 2.2 看板：左栏整栏换成 PR 列表

入口是侧栏大纲**最顶那一行**「看板」。切过去 = **整栏**换掉：`工作区 / 分支 / 标签 / 远端 /
已贮藏` 那几组一行都不画（不是收起来，是不画）；顶栏、日志、暂存带、状态栏一律不动。
底置那格 26pt 筛选框留着，但它筛的是**这一栏**（标题 / `#号` / 状态那句），和它筛大纲同一句话。

```
┌──────────── SIDEBAR 188pt ────────────┐
│ ‹ 仓库                          ← 回大纲 │
│ 代码托管  GitHub                 [刷新] │   11 次要 + 12 中黑 + 右端小按钮
│ ───────────────────────────────────── │
│ ● #12 加个按钮                  40 一行 │   左缘 x=12 蓝点 = 上次看过之后又有动静
│   有冲突 · 需要作者处理      12 DANGER  │
│   #13 修掉光标                        │
│   可以合并              11 ADD_FG      │
│ …                                     │
│ [筛选框 26pt                      ]   │
└───────────────────────────────────────┘
```

| 部件 | 规格 |
|---|---|
| 行 | 高 `BOARD_ROW_H 40`（§7 自拍），**两行字**：上格 `#号 + 标题` 12px `TEXT_PRIMARY`、下格状态一句话 11px 上色，各占半格（`BOARD_LINE_H 20`）、同一列起笔（`SIDE_TEXT_X 24`）；标题空着写「（无标题）」；两条都 `truncate`，不许横着溢出到日志区 |
| 蓝点 | `SIDE_DOT_X 12` / 直径 `SIDE_DOT_R×2 = 7` / `ACCENT`——和 §2「当前分支那颗蓝点」同一条网格、同一枚色。意思换成「**你上次看过之后它又动了**」：判据是库里那份 `seen[号] != pr.signature()`，不是新 PR。`signature()` = `state \| head sha \| CI 档 \| mergeable_state`——**不用 `updated_at`**，因为「检查跑完」不改 `updated_at`（实测），只看它等于「CI 从在跑到全绿」这件用户亲眼看见的事永远不亮点。**第一次打开这一栏**（那本账是空的）整栏不点亮：这一趟只默默建账（`Board::seeding`），关栏时结束——用户正看着它一条条填出来，此刻满屏蓝点是噪音 |
| 整行可点 | 记「看到这儿了」（内存 + 落库）**并且**在浏览器打开那条 PR。打开走 egui 的 `OutputCommand::OpenUrl`，不起 `open` 进程——命令队列无头量得到，跑测试也不会真弹浏览器 |
| 栏头 | 「代码托管」11 `TEXT_SECONDARY` + 平台名 12 `TEXT_PRIMARY`；右端一枚真的会重发请求的「刷新」11 |
| 状态一句话 | 一句、无动词、说清**挡路的那件事**。档位由 `provider::pr_status(pr, ctx)` 从 `state` / `draft` / `mergeable_state` × `ci` **两轴**拼出来，`ctx` 带两个不属于 PR 本身的事实（这一行在飞 = `fetching`、同一个 job 在别行也挂着 = `failing_elsewhere`）。顺序即优先级：`已合并` / `已关闭` → `草稿 · 作者还没准备好`（草稿挡住评审**和**合并，比冲突更上游）→ `有冲突 · 需要作者处理`（`dirty`：冲突是量出来的事实，检查全绿也合不了）→ CI 轴（`CI 正在跑 [· 已经挂了 N 个]` / `N 个检查没通过` / `N 个失败 · 在别的 PR 上也挂` / `N 个检查没过 · 但不挡合并`）→ 平台自己说完的几格（`可以合并` `clean` / `落后于目标分支 · 先更新` `behind` / `有检查没过 · 但不挡合并` `unstable`\|`has_warnings`）→ 检查已知且没坏才让 `等待评审`（`blocked`）说话 → `最新提交上还没有检查` / `正在看它卡在哪…` / `状态还没算出来`。**`blocked` 不许在检查没落地时说「等待评审」**：那格也可能是有一个检查还没跑完，这句会把活派给错的人；认不出的取值一律退最后一句，不猜 |
| 状态色 | 只给挡路的事上色（§原则①）：冲突 `DANGER`、可合 `ADD_FG`、等待评审与落后 `ACCENT_INK`、几个检查没过 `WARN_FG`、草稿与「不挡路的失败」与「大概无关的那几个失败」`TEXT_MUTED`、已合并/已关闭/没检查/正在看/认不出 `TEXT_SECONDARY`。**哪档配哪枚是自拍**，见 §7 |
| 「没有行」 | 四件事四句说法，不许合成一句：在飞 = 「正在取…」（`TEXT_MUTED`）；失败 = 把原因原话写出来（`DANGER`）；取过且真的没有 = 「没有开放的 PR」；一次都没取 = 「还没有取：按「刷新」取一次」 |
| 取数 | provider 只**拼** `ApiRequest`（列表 `GET {api}/repos/{owner}/{repo}/pulls?state=open&per_page=50&sort=updated`），发送在 `net::execute`，跑在后台线程；回复带 `board_seq`，对不上号的一律丢（换仓库/按刷新都会重新编号），**丢掉的回复不许把「在途」那一位解了** |
| 每行再问两次 | 列表端点**不给** `mergeable_state`，也不给检查（实测）→ 只对**画在可见区里**的行补两个请求：`GET {api}/pulls/{号}`（详情）与 `GET {api}/commits/{sha}/check-runs?per_page=100`（汇总，`aggregate_ci` 在核心层合一次）。可见性用行矩形 ∩ `ui.clip_rect()` 判；一帧最多 `ENRICH_IN_FLIGHT 6` 笔在飞，剩下的下一帧补（50 条 PR 不该被一次刷屏打成 100 个请求）。结果按 `(号, head sha)` 进 `Board::facts`：落回的那一笔**号和 sha 都要对上**才涂（旧那一版的「可以合并」挂在新提交上是这一栏最要命的那种谎）；「按刷新」把列表换成新的，`(号, sha)` 的缓存还有效就涂回去，同一版提交不再问第二遍；`sha` 变了就不涂。详情回 `unknown`（GitHub 那格是后台算的，第一次常常没有）**不当结论落地**：排一次 4 秒后的重问（`ctx.request_repaint_after`，静止的窗口自己醒来），最多试 `DETAIL_RETRY_MAX 2` 次才老实说「状态还没算出来」 |
| 没令牌 / 认不出托管 | **不发请求**，当场把原因写在栏上；补取那一半同一条规矩：没令牌就一行都不问，**也不许把「拼不出请求」记成「这一行取过了」**（否则用户回头绑上令牌、按下刷新，那些行永久 blank）。转圈转到超时再报错比一上来就写「未绑定 GitHub 令牌」慢一整圈 |
| 「看过」存哪儿 | 库里的 `settings`，键 `pr_seen2_<provider id>_<owner>_<repo>`（键里带 provider 与 `owner/repo`，fork 之间不共用账本），值 `{"号": "签名字串"}`。那个 `2` 是**账本代号**：判据从 `updated` 换成签名之后，旧账本里的值是另一种口径，留着会让每一条都「对不上」= 整栏蓝点；换代号 = 旧账本一次性作废（代价只是第一次进来不点亮）。读不懂就当**没看过**——一次写坏的记录不该把蓝点永久钉死 |

**这一节只覆盖读半场**。CI 那一档（`check-runs`）已经接上了——它就是上面「每行再问两次」
里的那一次，所以状态那句现在能说「几个检查没通过」「在别的 PR 上也挂」。
Run CI / Update branch & run CI / Retry failed jobs / Merge 那四枚**动作**按钮、
以及不克隆仓库的纯远程账号管理都还没做——看板目前仍挂在**已打开的仓库**上
（provider 是从这份快照的远端 URL 认出来的）。登记在 §7。

### 3.3 图序列车道色

`LANE_1..4` = 蓝 `#0969DA` / 绿 `#1A7F37` / 紫 `#8250DF` / 橙 `#CF6A00`（暗色自动提亮），
虚拟行圆环 `RING` = `#929291`。圆点半径 4pt、线宽 2pt 不变。
第 5 道往后取 `LANE_COLORS[道 % 4]`，即四色循环——spec 只给了四枚色，八爪合并靠拖宽图列解决（§2）。

**一截线的颜色跟着「还悬着的那一头」走。** 从本行圆点甩去接别的道的那一段（合并臂）按**落点**那道上色，
从别的道一路走进本行圆点的那一段（并回）按**来路**那道上色；判的都是「行的边界上不许换色」——
线接得上却换了色，看着仍然是一截断的（判据 `a_curve_is_coloured_by_the_end_that_is_still_hanging`）。

### 3.4 字级（Inter，已内嵌）

| 级别 | 规格 | 用途 |
|---|---|---|
| 标题 | 14px / 600 | 弹窗标题、空态标题、仓库名 |
| 正文 | 13px / 400 | 列表、侧栏子项、菜单、按钮内文字 |
| 次要 | 12px / 400 | 表头、作者、日期、说明、toast、徽章数字 |
| 辅助 | 11px / 400 | 分组头、状态栏、药丸、占位、行号 |

**字重只对拉丁与数字为真。** 内嵌字体里 Inter 有 400/500/600 三档（`assets/fonts/Inter-*.ttf`），
中文只有 `NotoSansSC-Regular.otf` 一档 —— 落到 CJK 字形上的 600 会被链尾的 Noto 画成 400，
看起来就是「标题不精神」。所以本表里的 600 生效范围是拉丁、数字、`M`/`A`/`D` 状态字母；
**中文标题靠字号与颜色分层，不靠字重**。要让中文也出 600，唯一诚实的办法是再内嵌
Noto Sans SC Medium（约 8MB，安装包接近翻倍），那是一个单独的决议，不要在建批时顺手做。

### 3.5 间距与圆角

- 间距：`4`（徽章、紧凑元素）/ `8`（图标-文字、面板横内边距）/ `12`（卡片内边距、面板竖内边距）/ `16`（分组间距）/ `24`（区块）。
- 圆角：`3` 状态色块 · `6` 按钮/输入/行/药丸(tab 用 999) · `10` 右键菜单 · `12` 卡片/弹窗/窗口。
- 所有分隔线 = `BORDER_SUBTLE` 1px；输入框描边 = `BORDER_STRONG` 1px，聚焦时描边转 `ACCENT` + 外圈 2px `ACCENT_SOFT`。

### 3.6 界面语言（两档：中文 / English）

§4.4 那排分段选择里的第四格，写在偏好卡「通用」页。**这是一档偏好，不是一次刷新**：

- 只有两档，没有「跟随系统」。从 Finder 起来的 GUI 进程读不到可靠的 macOS 语言档
  （`defaults read` 那条路在沙盒里、在没 TCC 授权的进程里都会给出和面板不一样的答案），
  一档点了没反应的「自动」比没有更糟（§1 那条「不摆按下去没反应的空壳」）。
- 文案是**取用时**按当前档位决定的（`tr!("中文","English")` 那一类，见 PROCESS 的 i18n 那批），
  不是两份界面。所以换档 = 下一帧重画，不需要重启。
- 有两处文字不是「下一帧」能带走的，换档那一刻要当场处理：
  ① 后台线程按当时语言拼好、缓存下来的那批（药丸上的「超前 2 个版本」、hunk 头、
  历史卡每条提交下面的补丁名）——换档要**重取一次快照**，否则一屏英文里挂着半截中文；
  ② 正开着的那张卡，它的标题和说明是打开那一刻算死的字符串——换档要**按新档重拼这张卡**，
  页签停在原来那一页（切语言不该把人从「代码托管」弹回「通用」）。
- 语言名本身不译：选项写的是它的母语名（「中文」/「English」），否则不会英文的人
  找不到切回去的那一格。英文档屏上唯一允许出现的汉字就是这一格。
- 落库一档（`gitx_prefs_lang`），下次启动读回同一份。

| §2 图列/提交号列能拖到多宽 | **没写**（spec 只给了 48 与 66 那一档） | 图列 `48 … 320`、提交号列 `48 … 240`（`GRAPH_W_MIN/MAX`、`SHA_W_MIN/MAX`），外加一挡**合起来**的：两列之和不得超过 `带宽 − 174 − 提交信息下限`（`col_room`） | 四个数全是拍的，各有依据但没有出处：**下限**就是 §2 那一档，再窄要把车道挤出列（图）或把 git 默认的 7 位短号切掉（提交号，而位数是「认得出这条提交最少要几位」）；图列上限 320 是「第 0 道中心 12 + 30 道」的容量档；提交号上限 240 装得下 33 位哈希，比 40 位更宽的那一格没人需要。判据 `column_widths_are_clamped_to_the_two_bounds` 把四枚字面值钉死，改档位必须连这一行一起改 |
| §2 提交信息那一格最少多宽 | **没写**（spec 只说它是弹性列） | `MSG_W_MIN 120`（**列位**，扣掉左右内缩与 8pt 余量后文字实际可用约 100pt） | 各列自己的上下限挡不住「两列一起顶到顶」：窗口地板 860 那档带宽只有 672，`320 + 240 + 96 + 78` 就已经超了。所以拖拽那一层还有一挡吃**带宽**的闸，且**新拖的那一列说了算、另一列不动**——拖不动就是它到头了，而不是「我拖了它却不理我」。120 是「还认得出一个词」的自拍档；判据 `two_columns_together_cannot_squeeze_out_the_message_column` 在 860 的窗里量帧：图列停在 312（不是 320）、提交号此后一格也拖不动 |
| §2 那条命中条多宽 | **没写**（列边界本身只有 1pt 那条竖线） | `COL_SPLIT_W 6.0`，居中压在竖线上 | 1pt 的线没人瞄得准，6pt 是「不用瞄准」的最低档（egui 自己的分隔条也在这一档）。命中条**只压在表头那一行**的高里：压在整带上就会吃掉行的点击，选提交比拖列宽常用得多 |
| §2 拖宽图列换来什么 | **没写** | 换来**车道容量**，不是把图放大：`LANE0_X 12` / `LANE_W 10` 是钉死的 | 道距跟着列宽缩放的话，同一本仓库在两个窗口宽度下会画出两张不同的图，那比越界更糟。固定道距顺带把「八爪合并（>4 道）画出 48pt 列」那条老边界交给用户：拖到 96pt 就装得下 8 道（判据 `widening_the_graph_column_buys_lane_capacity_for_an_octopus_merge`） |
| §2 拖宽提交号列换来什么 | **没写** | 多看几位哈希，由 `revision_text` 按**列宽**算位数（`SHA_CHAR_W 6.6`、`SHA_PAD 8.0` 反推自 §2 那格 66 = 12 内缩 + 7 位 + 8 余量） | 两个常数都是从 §2 已有的那一档反推的，不是新拍的第三组数。规则两条：窄的时候**一位都不减**（减就可能撞号、认错提交），宽的时候只从**完整号**里往后补（补出一个 git 没给过的号更糟）。第 5 道以后的车道色取 `LANE_COLORS[道 % 4]`（spec 只给了四枚色，同色相循环比再造四枚没依据的色诚实） |
| 冲突的合并报的是哪句话 | **没写**（§5.5 只有「toast 说人话」） | `run_git` 失败时 **stderr 空了就读 stdout**，两条都空才报退出码 | 实测：git 把冲突报告（`CONFLICT (content): …`、`Automatic merge failed; …`）写在 **stdout** 上，stderr 反而是空的 —— 只读 stderr 的话，用户点「合并」撞出冲突，弹出来的是 `git command failed: ` 后面一个字都没有。原文进了解释所以用户拿它搜得到东西 |
| 「进行中」还缺的那一格 | §2 状态栏只写「进行中操作」 | `Op` 补 `rev`（`MERGE_HEAD` / `CHERRY_PICK_HEAD` / `REBASE_HEAD` 的第一行），`RepoStatus` 投影成 `op_rev` | 被合进来的那几条**只从 `MERGE_HEAD` 可达**，而 `git log` 只走 HEAD，于是冲突时历史列表里没有正被合并的提交——用户报的「历史记录列表就显示不出来」就是这一格没有的代价。读文件而不是 `git rev-parse`：后者又一次 fork，而 `op_at` 已经在同一次 `status` 里摸过这批文件。**形状那一挡（≥40 位纯十六进制）不许省**：垃圾串进了 argv 回来一句 `unknown revision`，界面变成「历史列表整个空掉」，比不显示更糟 |


| 窗口图标挂在哪一档 | **没写**（§1 只说「macOS 的 Dock 图标是圆角底板 + 提交图」） | 只有**非 macOS** 那一档挂 `with_icon`（`#[cfg(not(target_os = "macos"))]`）；macOS 的 Dock 那张仍由 `.app` 里的 `.icns` 出 | winit 0.30 在 mac 上的 `set_window_icon` 是**空函数**（源码注释「macOS doesn't have window icons」），而我们为这张画不出来的图付「解一次 1024² PNG + 常驻在 viewport 属性里」。素材只有一份（`assets/icon.png`），两边不会长得不一样；代价与 A/B 数见 PROCESS 同日表，判据 `the_window_icon_is_only_paid_for_where_the_os_reads_it` |
| 差异一行的正文由谁持有 | **没写**（§3 只写行号、颜色、折叠） | 整份补丁**一块** `Arc<str>`，每行只记 `[start, end)` 两个 `u32`（`DiffText`）；块头与文件头那两句现写的文案各自一小块 | 30 002 行的 diff 如果一行一个 `String`，正文只有 1.4 MB，但那是 30 001 次小块分配——**账在分配次数上，不在字节数上**。所以定的是形状（一块文本 + 区间），不是某个 MB 目标；形状由 `the_diff_body_shares_one_text_block` 与 `a_crlf_patch_lays_out_the_same_lines_as_an_lf_one` 钉，实测数在 PROCESS 同日表 |
| `git` 的 stdout 怎么变成 `String` | **没写** | `decode_owned(Vec<u8>)`：合法 UTF-8 时**接管那块缓冲**（不复制），非法那一档才转码且**保留合法前缀** | 旧写法 `from_utf8_lossy(..).into_owned()` 在峰值里同时握住字节缓冲和复制出来的正文，等于每取一次补丁多复制一份全文。GBK 那档不能删：路径名是仓库自己的字节，报错等于整本仓库读不动。判据 `git_stdout_is_taken_over_rather_than_copied` 量的是**指针**，不是长度 |
| 差异区怎么把提交里的一块/一行撤出来 | **没写**（spec 只有 hunk 头与增删行） | 提交差异的 hunk 头右端一枚「回滚区块」；右键增/删行「回滚这一行」。两条都只反打回**工作区** | 核心层是两条 `git apply -R`（整块补丁 / 零上下文单行补丁），HEAD 与索引都不动；实测反打一块之后 `rev-parse HEAD` 不变，另一块原样留着。按钮只挂**提交**那一格：工作区已经有暂存/放弃，贮藏的补丁反打回工作区等于替用户丢改动。行级的文件名从**它自己那条文件头**上取（整条提交的补丁跨文件），正文去掉行首 `+`/`-` 才交给 core；行号与「后来改过」的校验全在 `git::revert_line`。不叠确认卡：撞上后来改过的行 core 会拒、文件一个字节不动（判据 `a_hunk_that_no_longer_matches_is_refused_and_the_file_is_untouched`） |
| 右键菜单怎么记住「哪一行」 | **没写** | 右键那一帧把补丁下标 latch 进 `diff_menu_line`；菜单关掉（`container_context_menu` 回 `None`）那一帧清掉；换差异时在 `request()` 里清 | 菜单一开指针就移到菜单上，再按「指针底下是哪一行」去问会问空——那一项会在菜单开着的时候自己消失。不给每行挂一个 `context_menu`：那会和标签选区抢 hover（用户 2026-10-26 报的「选中内容右击就没了」）。只有 `Kind::Add`/`Kind::Del` 才出这一项，上下文行、文件头、hunk 头都不给 |
| 回滚之后界面怎么说话 | **没写**（§5.5 只有失败时的 toast） | 成功也发一条 `Msg::Note`：`已把第 N 块回滚到工作区（历史没动）` / `已回滚这一行到工作区（历史没动）` | 落点在工作区，而用户正看着那条提交的差异——那一格一个字都不会变，不说一句就等于「点了没反应」。这两条是**唯一**需要成功提示的动作；其余动作在文件表/日志上自己就换了 |
