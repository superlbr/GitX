# GitX 界面设计规范

> 本文是 UI 的唯一事实来源。实现（`src/ui/theme.rs` 常量、`app.rs` 布局、`geometry.rs` 判据锚点）
> 以这里的数字为准；视觉改动先看这张图，再动代码。
>
> 定位：**现代化清爽的 Git 客户端**（向 GitHub Desktop / Fork 靠），不再是任何既有产品的复刻。
> 大留白、柔和灰阶、清晰信息层级；颜色只给状态和层级，不装饰。
>
> 可视化预览：[design-preview.html](design-preview.html)（浏览器直接打开，右上角可切亮/暗）。

## 1. 设计原则

1. **灰阶打底，主色点睛**：界面 95% 是白与灰的层级；主色 `#0969DA` 只出现在选中、链接、主按钮、当前分支。
2. **信息靠层级，不靠颜色**：列表正文一律 `TEXT_PRIMARY`；主次用字号字重和灰度拉开，SourceTree 式「深色正文 + 浅灰次要」作废。
3. **1px 分隔线分区**，不再用底色带硬切（侧栏、表头、状态栏除外，它们是 chrome）。
4. **4/8 网格**：一切间距、尺寸落在 4 的倍数上。
5. **弹窗即闸**：所有不可逆操作先过确认卡；反馈走 toast，不用弹窗报成功。

## 2. 首页（主窗口）布局

```
┌──────────────────────────────────────────────────────────┐
│ HEADER 46pt  🚦 仓库tab(胶囊)  分支·↑↓      动作按钮组 »  │  ← 白底 + 下 1px 分隔线
├────────┬─────────────────────────────────────────────────┤
│ SIDEBAR│  LOG 区（表头 28 + 行 28 × N，可滚）              │  ← 侧栏 188pt 灰底
│ 188pt  ├─────────────────────────────────────────────────┤
│ 分组   │  STAGING 带 240pt：文件表 330pt │ 差异区           │  ← 可拖高，1px 分隔
│ +筛选  ├─────────────────────────────────────────────────┤
│        │  STATUS 24pt                                   │  ← 白底 + 上 1px 分隔线
└────────┴─────────────────────────────────────────────────┘
```

| 区域 | 尺寸 | 要点 |
|---|---|---|
| HEADER | 46pt，横贯整窗 | 红绿灯 inset 92pt 不变（`TITLE_INSET`）；仓库 tab 为胶囊开关（高 26、圆角 999，选中 = 主色浅底深字）；选中分支名 12px + `↑↓` 计数；右侧动作按钮 28px 命中、圆角 6、hover 浅灰；窗口收窄时溢出收进 `»` 菜单 |
| SIDEBAR | 188pt 固定，灰底 | 分组头 = 11px 灰字 + 右对齐计数，无图标；子项行高 26，选中 = 浅蓝药丸（圆角 6）；当前分支 = 蓝点 + 中黑字；底置筛选输入框 26pt |
| LOG | 表头 28pt + 行 28pt | 列：图 48 \| 提交信息（弹性）\| 作者 96 \| 日期 78；选中 = 浅蓝底 + 左缘 2px 主色条；hover 浅灰；虚拟行（未提交）浅灰底整行；ref 药丸见 §4.5 |
| STAGING | 默认 240pt，可拖 | 文件表 330pt：行高 24，状态色块 12pt 圆角 3，圆角勾选框 13pt；底置提交框（摘要 + 三行描述 + 修正勾 + 主按钮）；右侧差异区：hunk 头灰底、增删行浅绿/浅红整行底 |
| STATUS | 24pt，横贯整窗 | 左：分支 · ↑↓ · 进行中操作；右：仓库路径；11px 灰字 |

窗口最小尺寸 `MIN_W 860 × MIN_H 394`（= HEADER 46 + LOG 下限 84 + STAGING 240 + STATUS 24；
LOG 下限 = 表头 28 + 2 行 × 28）。**LOG 区不允许归零**：`46+240+24=310` 那种算法在最小尺寸下
给出一个看不见任何提交的窗口，那是坏掉的尺寸而不是紧凑的尺寸。STAGING 带可拖，档位
`120 … 窗口余量`。

**空态（没有打开仓库时）**：LOG 区居中显示——20/600「还没有打开的仓库」+ 13px 灰字说明 +
`[克隆仓库…]`（幽灵）`[添加仓库…]`（主色）两枚按钮。空态下侧栏**保留 188pt 灰底外壳**，
里面只画一行 11px 灰字「还没有添加仓库」——外壳跟着内容消失会让窗口在空态/常态之间宽度跳变。

### 2.1 侧栏首页：最近与分组

仓库是**分组**的（SourceTree 的仓库浏览器就是「组 + 组内仓库」，还带全部展开/折叠所有/按名称
排序/按类型排序）。侧栏那 188pt 在首页 tab 上承载的就是这一层，自上而下：

| 段 | 内容 | 规格 |
|---|---|---|
| 顶部分段选择 | `最近` / `分组` 两档 | §4.4 那套：容器 `BG_INSET` 圆角 8，高 30，左右各 8 内边距（内容宽 172） |
| 分组 | 组头 + 组内仓库行 | 组头 = §2 现成规格（11px `TEXT_SECONDARY` + 右对齐计数，无图标），点击折叠；仓库行高 26、缩进 8、正文 13px `TEXT_PRIMARY`，副行 11px `TEXT_MUTED`（分支 · `↑↓`） |
| 最近 | `recent_open` 前 8 条 | 行高 26，同上行样式；副行把**组名放在最前**（`组名 · 分支 · ↑↓`）而**不重画组头**——「最近」是跨组的，插组头会把 8 条切成几段，破坏「一屏看到最能上手的几个」这个唯一目的 |
| 底部 | 筛选输入框 | 26pt，§2 现成规格，两档共用 |

**组只有一层，不嵌套。** 落库是 `repos.group_name TEXT NOT NULL DEFAULT ''`，空串读作「未分组」，
改名/移出组都是一条 UPDATE。嵌套会把折叠状态、排序、拖放三套判据各乘一层。**「一层」是我们自己的
决定**：nib 取证只读到 `新建仓库组` / `全部展开` / `折叠所有` / `按名称排序` / `按类型排序` 这些控件，
**组的嵌套深度没有量过**，别把这句话当成"照抄 SourceTree"。
老库补这一列沿用 `last_fetched_at` 的手法：`has_column` 判缺再 `ALTER TABLE`，不要求重建数据库。

### 3.3 图序列车道色

`LANE_1..4` = 蓝 `#0969DA` / 绿 `#1A7F37` / 紫 `#8250DF` / 橙 `#CF6A00`（暗色自动提亮），
虚拟行圆环 `RING` = `#929291`。圆点半径 4pt、线宽 2pt 不变。

### 3.4 字级（Inter，已内嵌）

| 级别 | 规格 | 用途 |
|---|---|---|
| 标题 | 14px / 600 | 弹窗标题、空态标题、仓库名 |
| 正文 | 13px / 400 | 列表、侧栏子项、菜单、按钮内文字 |
| 次要 | 12px / 400 | 表头、作者、日期、说明、toast、徽章数字 |
| 辅助 | 11px / 400 | 分组头、状态栏、药丸、占位、行号 |

**字重只对拉丁与数字为真。** 内嵌字体里 Inter 有 400/500/600 三档（`assets/fonts/Inter-*.ttf`），
中文只有 `NotoSansSC-Regular.otf` 一档 —— 落到 CJK 字形上的 600 会被链尾的 Noto 画成 400，
看起来就是「标题不精神」。所以本表里的 600 生效范围是拉丁、数字、`M`/`A`/`D` 状态字母；
**中文标题靠字号与颜色分层，不靠字重**。要让中文也出 600，唯一诚实的办法是再内嵌
Noto Sans SC Medium（约 8MB，安装包接近翻倍），那是一个单独的决议，不要在建批时顺手做。

### 3.5 间距与圆角

- 间距：`4`（徽章、紧凑元素）/ `8`（图标-文字、面板横内边距）/ `12`（卡片内边距、面板竖内边距）/ `16`（分组间距）/ `24`（区块）。
- 圆角：`3` 状态色块 · `6` 按钮/输入/行/药丸(tab 用 999) · `10` 右键菜单 · `12` 卡片/弹窗/窗口。
- 所有分隔线 = `BORDER_SUBTLE` 1px；输入框描边 = `BORDER_STRONG` 1px，聚焦时描边转 `ACCENT` + 外圈 2px `ACCENT_SOFT`。

## 4. 组件规范

### 4.1 按钮

| 种类 | 样式 | 用途 |
|---|---|---|
| 主按钮 | `ACCENT` 实心白字 12/600，高 28，圆角 6，padding 12 | 每卡最多一枚：提交/推送/拉取/确定 |
| 幽灵按钮 | 白底 + `BORDER_STRONG` 描边，字 `TEXT_SECONDARY` | 取消、全部暂存、次要动作 |
| 危险主按钮 | `DANGER` 实心白字 | 确认卡里的删除/丢弃/强推 |
| 图标按钮 | 28×28，圆角 6，hover `BG_HOVER`，图标 14px | 顶栏动作组、× 关闭 |

### 4.2 输入框：高 30，圆角 6，占位 `TEXT_MUTED`；多行描述三行起步。
### 4.3 开关：40×22 胶囊，开 = `ACCENT`、关 = `BORDER_STRONG`，滚珠 18 白。
### 4.4 分段选择（添加仓库三档 / 偏好页签）：容器 `BG_INSET` 圆角 8，选中段白底药丸 + 细阴影。

### 4.5 ref 药丸（提交信息列）

浅底 + 同色描边 + 深色字，圆角 999，11/600：

| 种类 | 底 / 边 / 字 |
|---|---|
| 分支 / 远端 | `ACCENT_SOFT` / `ACCENT_LINE` / `ACCENT_INK` |
| 超前/落后胶囊 | 深藏青 `#0550AE` 底白字（贴死在前一枚右侧） |
| 标签 | `ADD_BG` / `#B7E0C2` / `ADD_FG` |

### 4.6 选中态（所有列表通用）

浅蓝底 `ACCENT_SOFT` + 左缘 2px `ACCENT` 竖条 + 文字保持 `TEXT_PRIMARY`（可加粗）。
**不再使用实心蓝底白字。**

## 5. 弹窗体系

### 5.1 遮罩与卡片

- 遮罩：整窗 `rgba(31,35,40,.48)`；点遮罩 = 取消；Esc = 取消；Enter = 主按钮。
- 卡片：白底、圆角 12、1px `BORDER_SUBTLE` 描边、真阴影（offset 0/8、blur 24、黑 40%）。
  宽度三档：确认卡 380 · 标准卡 440（新建分支/标签/贮藏/合并）· 宽卡 560（提交/拉取/推送/偏好/添加仓库）。
- 打开时 120ms 淡入 + 上移 4pt；焦点默认进第一个输入框。

### 5.2 表单卡

- 内边距 16；标题 14/600 + 右上 ×（幽灵图标按钮）；说明 12px `TEXT_SECONDARY`。
- 标题/正文/按钮区之间**只靠间距分组，不画分隔线**（现实现里的标题带下划线与 footer 上划线废除）。
- 底部按钮区高 52，右对齐： `[取消]` 幽灵在左、主按钮在右，间距 8。
- 偏好卡无「取消」（开关当场生效），保留 × / Esc 关闭。

### 5.3 确认卡（宽 380）

红色警示圆标（`DEL_BG` 底 + `DANGER` 叹号）+ 标题 14/600 + 说明 12px +
`[取消]` + `[红色主按钮]`。对象名（文件/分支）在标题里加粗语义化，说明里不复读。

### 5.4 右键菜单（分支/提交/标签/文件行）

圆角 10、内边距 4、行高 28、字号 13、hover `BG_HOVER`；分组用 1px 分隔线；
危险项 `DANGER` 字重 500；宽度随内容（最小 200），细阴影。

### 5.5 toast

底部居中（状态栏上方 8pt）、白底圆角 8、1px `BORDER_SUBTLE`、细阴影；
13px 正文 + ×（hover 圆角 4）；8 秒淡出，点击整张即关。位置与生命周期不变，只换皮肤。

## 7. 落地注记（spec 做不到 / 我们自己拍的数）

这一节只记两件事：**spec 写了但这一栈画不出来的**，和**spec 没写、实现自己拍的数**。
逐带追加。这里没有一行是"量出来的"，别拿它当实测值引用。

| 出处 | spec 写的 | 现在落的 | 为什么 |
|---|---|---|---|
| §2 仓库 tab | 圆角 999 | `TAB_PILL_R 13`（= 26 的半高） | egui 的 `CornerRadius` 只有 u8 半径，没有 999 那档；半高就是胶囊，视觉上等价 |
| §2 添加仓库那枚 | 1px **虚线** 描边 | 1px 实线 `BORDER_STRONG` | egui 0.37 的 `Stroke` 没有 dash，虚线画不出来。要么以后用一排小方点近似，要么改 spec——现在判据钉的是"有一枚描边胶囊"，不是"虚线" |
| §4.1 动作按钮 | 线描 SVG 图标 | 字体链里**确实存在**的 Unicode 字形（⊕ ↓ ↑ ⇄ …） | 真 SVG 排在 S6-7（S6-6 已被弹窗体系占用）。换锚时先把「画出来的每个码位都得有字形」做成判据（`every_rune_the_shell_paints_has_a_glyph`）：上一版有七个是豆腐块，那不是配色问题，是根本没字 |
| §2 圆角勾选框 **13pt** | 13 | `CHK_S 13`（旧 `13.5` 作废） | §2 给的是整数档，参考图三枚量到都是 13.5。差的半像素走 spec：所有以 13.5 为锚的落点（无方框那栏文字 `8+13+7=28`，旧 28.5）跟着挪。判据 `the_section_box_sits_in_its_own_column` 认方框用的是 ±0.6 的窄容差——原来跟着 `near` 的 ±1.5，`CHK_S` 从 13 改 12 都能被认成方框、判据白跑（S6-5 变异实测）。 |
| §2 `MIN_W 860` | 860 | 860，但**没有内容判据钉住这个数** | 2026-10-25 实测：撞车那条判据在 800 还绿、760 才红，860 下面有 60–100pt 空档。所以 860 只由字面值判据钉（见 PROCESS 同日变异表） |
| §2「窗口收窄时溢出收进 `»` 菜单」 | 有这一档 | **没实现** | 顶栏现在是 11 枚按钮全平铺。上一条那个空档就是它没实现的直接后果：靠"缩到 760 才撞"顶着 |
